# PW-038: Tier Zero computers take updates from WSUS over HTTP

**Category:** Hygiene
**Typical owner:** Windows server team, with the AD team

## What this finding means
A GPO that applies to domain controllers, CA servers or other Tier Zero
computers points Windows Update at a WSUS server with an `http://` URL
(Computer Configuration > Administrative Templates > Windows Components >
Windows Update > Specify intranet Microsoft update service location). The
computers then check for updates, and download them, over plain HTTP.

Pathwarden reads the setting from the GPOs' `Machine\Registry.pol` files in
SYSVOL (the values `WUServer` and `UseWUServer` under
`HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`), and works out
which GPO wins on each computer from the GPO links above it. Only
Pathwarden's built-in collector reads these files: with SharpHound data
this rule can't run, and that is not a clean result.

## Why attackers care
Over HTTP nothing proves that the answer to an update check comes from the
WSUS server. Anyone who can sit on the network path (ARP or DHCP spoofing,
a rogue WPAD proxy, a compromised switch) can answer with an "update" of
their own. Windows Update runs it as SYSTEM, as long as it is signed by
Microsoft, and tools such as PsExec are (WSUSpect, pywsus, SharpWSUS). On a
domain controller that is the whole domain.

## Before you change anything
- The finding is inferred: a WMI filter or security filtering may keep the
  GPO off some of the computers it lists. Check with `gpresult /r` on one.
- Switching to HTTPS needs a certificate on the WSUS server that the
  clients trust, with the server's name as the URL spells it.
- Every client of the GPO changes at once, not only the Tier Zero ones.

## Fix
### Option A: WSUS over TLS
1. Request a certificate for the WSUS server's name and bind it to the
   `WSUS Administration` site in IIS (port 8531).
2. Require SSL on the `ApiRemoting30`, `ClientWebService`, `DSSAuthWebService`,
   `ServerSyncWebService` and `SimpleAuthWebService` virtual directories,
   then run `WsusUtil.exe configuressl <server name>`.
3. In the GPO the finding names, change both URLs (update service and
   statistics server) to `https://<server name>:8531`.
### Option B: a WSUS server for Tier Zero only
Give the Tier Zero computers their own WSUS server, run and administered
from Tier Zero, on the Tier Zero network, over TLS as in option A. The
WSUS server is then part of Tier Zero (PW-025 says so until you declare it).

### PowerShell
```powershell
# What a computer uses now (run on a domain controller)
Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' |
    Select-Object WUServer, WUStatusServer
Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU' |
    Select-Object UseWUServer

# The setting in the GPO
Get-GPRegistryValue -Name '<GPO name>' `
    -Key 'HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' -ValueName WUServer
```

## Verify
After `gpupdate /force` on a Tier Zero computer, `WUServer` starts with
`https://` and `wuauclt /detectnow` (or Settings > Windows Update) finds
updates. Collect again with the built-in collector: the finding is fixed.
A collection that didn't read SYSVOL keeps it open, as can't tell.

## Rollback
Put the `http://` URLs back in the GPO. Clients pick them up at their next
Group Policy refresh.
