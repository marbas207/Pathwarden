# PW-016: AD CS ESC3: enrollment agent abuse

**Category:** Attack path
**Typical owner:** PKI / AD CS administrators

## What this finding means
Accounts and groups outside Tier Zero can enroll in a template that issues enrollment agent certificates (Certificate Request Agent EKU, or any purpose). With such a certificate they can request a second, logon-capable certificate on behalf of any other user, and the CA where that second template is published does not restrict which agents may do this. Domain controllers trust both CAs for logon.

## Why attackers care
This is ESC3 from SpecterOps' "Certified Pre-Owned". Enrollment agents exist so a smart card team can issue cards for other people. An attacker who can enroll as an agent (tools such as Certipy automate both steps) first gets an agent certificate, then requests an authentication certificate "on behalf of" a Domain Admin and logs on as them with PKINIT. Version 1 templates such as the built-in User template accept on-behalf-of requests from any agent by design, which is why unrestricted agents are dangerous.

## Before you change anything
- Identify who holds valid agent certificates today: in certsrv.msc > Issued Certificates, filter on the agent template, or run
  `certutil -config "<CAHost>\<CAName>" -view -restrict "CertificateTemplate=<AgentTemplateOID>" -out "RequestID,RequesterName,NotAfter"`
- Find out whether anyone legitimately enrolls on behalf of others (smart card issuance stations, a badge or MFA team). Those few accounts are the only ones that should keep the agent template.
- Check which templates the agents need to enroll for (usually a smart card logon template), and for which users.

## Fix
### Option A: Restrict enrollment agents on the CA (recommended)
1. Open certsrv.msc, right-click the CA > Properties > **Enrollment Agents** tab.
2. Select **Restrict enrollment agents**.
3. Under Enrollment agents, add only the group of legitimate agents and remove Everyone.
4. Under Certificate Templates, add only the templates they need to issue (for example the smart card logon template) and remove <All>.
5. Under Permissions, allow only the users they should enroll for (for example a smart card users group) and deny privileged groups such as Domain Admins and Enterprise Admins.
6. Click OK. Repeat on every CA that publishes the target template.

### Option B: Lock down the agent template
1. certtmpl.msc > agent template > Properties > **Security** tab: remove Enroll (and Full Control, which includes it) from broad groups, grant it only to the legitimate agent group, which the PKI administrators manage.
2. **Issuance Requirements** tab: tick **CA certificate manager approval** so a certificate manager reviews each agent certificate.
3. If nobody uses enrollment agents, unpublish the agent template (certsrv.msc > Certificate Templates > Delete) and revoke outstanding agent certificates.

### Then: review certificates already issued
Certificates issued before the fix stay valid. In certsrv.msc > **Issued
Certificates**, check the certificates issued on behalf of others for requests
nobody expected, and revoke them.

### PowerShell / certutil
```powershell
# Templates the CA issues; confirm the agent template is (or is no longer) listed
certutil -config "<CAHost>\<CAName>" -CATemplates

# Unpublish the agent template if it is not needed
certutil -config "<CAHost>\<CAName>" -SetCATemplates -<AgentTemplate>

# Revoke an outstanding agent certificate by serial number (reason 4 = superseded)
certutil -config "<CAHost>\<CAName>" -revoke <SerialNumber> 4
```

## Verify
- certsrv.msc > CA Properties > Enrollment Agents shows "Restrict enrollment agents" with only the intended agents, templates and users.
- A test on-behalf-of request from a non-agent account (or for a Domain Admin) is denied.
- Collect again (or use Retest on the finding) and confirm the finding ID is gone. Pathwarden detects restrictions only when the collector reads them from the CA registry (SharpHound reports this; some collectors do not).

## Rollback
Select "Do not restrict enrollment agents" on the Enrollment Agents tab, or restore the template's Security and Issuance Requirements settings, or re-publish the template with `certutil -config "<CAHost>\<CAName>" -SetCATemplates +<AgentTemplate>`.
