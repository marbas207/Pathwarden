# PW-039: Tier Zero computers are virtual machines of an unmodeled hypervisor

**Category:** Hygiene
**Typical owner:** Virtualization team, with the AD team

## What this finding means
Domain controllers, CA servers or other Tier Zero computers run VMware
Tools, so they are VMware virtual machines. Pathwarden reads this from the
Tier Zero settings file each server's admins write with
`Get-PathwardenTierZeroSettings.ps1` (the key
`HKLM\SOFTWARE\VMware, Inc.\VMware Tools`).

The ESXi hosts and the vCenter that run these virtual machines are not in
the directory, so Pathwarden can't show who administers them. Its attack
paths stop at the virtual machine, and a path through the hypervisor is not
counted.

## Why attackers care
Whoever administers an ESXi host or its vCenter controls every virtual
machine on it without signing in to it: they can copy a domain controller's
disk and read `NTDS.dit` offline (every password hash, the `krbtgt` key),
take a snapshot with its memory, or open its console. Ransomware groups go
for ESXi and vCenter for that reason, and the ESX Admins group
(CVE-2024-37085, PW-029) makes it easier.

## Before you change anything
- List the ESXi hosts, clusters and vCenters that run the computers the
  finding names (vCenter's inventory, or the VM's summary page).
- List who administers them: vCenter roles and permissions, ESXi local
  accounts, the identity source vCenter trusts, and the backup and
  replication accounts with access to the datastores.
- A Tier Zero settings file over 90 days old can show VMware Tools but can't
  show it gone; run the script again after moving a server.

## Fix
### Option A: run Tier Zero on a Tier Zero hypervisor
Give the Tier Zero virtual machines their own ESXi cluster (or a dedicated
vCenter), administered only by Tier Zero admins, from Tier Zero admin
workstations, on a management network apart from the rest.
### Option B: harden the shared hypervisor
1. Grant vCenter and ESXi administration only to Tier Zero admins, and
   remove vCenter's trust in identity sources outside Tier Zero.
2. Turn off the ESX Admins automatic grant on every ESXi host joined to the
   domain (`Config.HostAgent.plugins.hostsvc.esxAdminsGroupAutoAdd`).
3. Encrypt the Tier Zero virtual machines (VM encryption with a key
   provider), so a copied disk can't be read elsewhere.
4. Keep the datastores and the backups of these virtual machines out of
   reach of anyone outside Tier Zero.

Then accept this finding as a risk with the reason, so it stays in view.

### PowerShell
```powershell
# On a Tier Zero computer: is it a VMware virtual machine?
Test-Path 'HKLM:\SOFTWARE\VMware, Inc.\VMware Tools'
(Get-CimInstance Win32_ComputerSystem).Manufacturer
```

## Verify
Run `Get-PathwardenTierZeroSettings.ps1` on the servers again and analyze
with the new files. The finding stays while VMware Tools is there; accept
it as a risk once the hypervisor is Tier Zero. A run without a current file
from a server keeps the finding open, as can't tell.

## Rollback
Nothing changes on the servers. Remove an accepted risk to see the finding
again.
