# PW-037: Seamless SSO Kerberos key not rolled over

**Category:** Hygiene
**Typical owner:** AD / identity team, with the Entra ID team

## What this finding means
The Seamless SSO computer account (`AZUREADSSOACC`) has a Kerberos key that
was last changed more than 30 days ago (the Old Seamless SSO key field in
Settings > Rules changes the limit). Entra ID shares that key with the
on-premises domain to accept Kerberos tickets for Seamless Single Sign-On.
Pathwarden reads the age from the account's `pwdLastSet`.

## Why attackers care
Whoever has the key can forge a Kerberos service ticket for the account (a
silver ticket) for any synchronized user, and sign in to Entra ID as that
user. The key never changes on its own, so a key stolen once, through DCSync
or a domain controller backup, keeps working until someone rolls it over.
Microsoft recommends rolling it over at least every 30 days.

## Before you change anything
- The rollover runs on the Entra Connect server, as a Hybrid Identity
  Administrator in Entra ID and a Domain Admin of each forest that has the
  account.
- Kerberos tickets already issued for the account stay valid until they
  expire (10 hours by default). Users don't notice the rollover.

## Fix
### Option A: Roll the key over with Microsoft's module
1. On the Entra Connect server, open PowerShell in
   `%ProgramFiles%\Microsoft Azure Active Directory Connect`.
2. Import the `AzureADSSO.psd1` module, sign in with
   `New-AzureADSSOAuthenticationContext`, and list the forests with
   `Get-AzureADSSOStatus`.
3. For each forest, run `Update-AzureADSSOForest` with the credentials of a
   Domain Admin of that forest.
4. Repeat at least every 30 days. A scheduled task with a dedicated account
   is common; that account is then Tier Zero.
### Option B: Seamless SSO is no longer used
Turn Seamless SSO off in Entra Connect, and delete the `AZUREADSSOACC`
computer account in each forest.

### PowerShell
```powershell
cd "$env:ProgramFiles\Microsoft Azure Active Directory Connect"
Import-Module .\AzureADSSO.psd1
New-AzureADSSOAuthenticationContext
Get-AzureADSSOStatus | ConvertFrom-Json
$creds = Get-Credential   # a Domain Admin of the forest, DOMAIN\user
Update-AzureADSSOForest -OnPremCredentials $creds

# The age, before and after
Get-ADComputer AZUREADSSOACC -Properties PasswordLastSet | Select-Object Name, PasswordLastSet
```

## Verify
`Get-ADComputer AZUREADSSOACC -Properties PasswordLastSet` shows today's
date. Use Retest on the finding: it re-reads
the account, and the finding is fixed.

## Rollback
A rollover can't be undone, and doesn't need to be: Seamless SSO keeps
working with the new key.
