# PW-013: Accounts that may have an empty password

**Category:** Hygiene
**Typical owner:** AD / identity team

## What this finding means
These enabled accounts have the PASSWD_NOTREQD flag (userAccountControl 0x20) set. With this
flag, the account is exempt from the domain password policy and may have an empty password. Old
provisioning tools or scripted account creation often leave the flag behind.

## Why attackers care
Attackers enumerate accounts with this flag (any domain user can read userAccountControl) and try
a blank password against each one. A hit gives a working domain account with no cracking needed
(Valid Accounts: Domain Accounts, MITRE ATT&CK T1078.002). If any of these accounts is privileged,
Pathwarden rates the finding higher because it is a direct route to Tier Zero.

## Before you change anything
- Find out which tool created the accounts. Some provisioning systems set the flag again on their
  next sync. Fix the tool's template as well.
- Clearing the flag does not change the current password. If the password is empty,
  the account keeps working with an empty password until you reset it.
- For service accounts, find where the password is configured before resetting it (see PW-010).

## Fix
### Option A: Clear the flag and reset the password (recommended)
1. Clear the flag with PowerShell (below). Active Directory Users and Computers does not show
   this flag; to do it in the GUI, use the **Attribute Editor** tab and remove 0x20 from
   **userAccountControl**.
2. In **Active Directory Users and Computers**, right-click the account > **Reset Password** and
   set a strong password.
3. For service accounts, update the password wherever it is configured and restart the services.

### Option B: Disable unused accounts
If an account in the list is not needed, disable it instead (`Disable-ADAccount`).

### PowerShell
```powershell
Import-Module ActiveDirectory

# List enabled accounts with PASSWD_NOTREQD (0x20)
Get-ADUser -LDAPFilter "(&(userAccountControl:1.2.840.113556.1.4.803:=32)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))" |
    Select-Object SamAccountName

# Clear the flag
Set-ADAccountControl -Identity "<Account>" -PasswordNotRequired $false

# Reset the password so it meets policy (prompts without echoing)
Set-ADAccountPassword -Identity "<Account>" -Reset -NewPassword (Read-Host -AsSecureString "New password")
```

## Verify
```powershell
Get-ADUser -Identity "<Account>" -Properties PasswordNotRequired |
    Select-Object SamAccountName, PasswordNotRequired
```
`PasswordNotRequired` should be `False`. Collect again (or use Retest on the finding) and confirm the finding ID is gone (or lists
fewer accounts).

## Rollback
`Set-ADAccountControl -Identity "<Account>" -PasswordNotRequired $true` restores the flag. This
is rarely needed: an account with a valid password works the same with or without the flag.
