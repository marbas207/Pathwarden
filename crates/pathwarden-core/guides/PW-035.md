# PW-035: Tier Zero computer managed by SCCM from outside Tier Zero

**Category:** Attack path
**Typical owner:** the SCCM (Configuration Manager) team, with the Tier Zero owners

## What this finding means
A Tier Zero computer (a domain controller, a CA server, a computer you declared Tier
Zero) is an SCCM client, and accounts or groups outside Tier Zero can administer it
through SCCM: a Full or Application Administrator of a collection that holds
it, an administrator of the whole site, or whoever controls the site
database. Each of them can deploy an application, script or task sequence
that runs as SYSTEM on the computer.

There is one finding per computer. The evidence comes from ConfigManBearPig (an
OpenGraph file, see `docs/opengraph.md`): its role-based administration,
client and site database records. Its "assumed" relay and co-location
relationships are never part of the finding. PW-025 reports the site server itself
when the directory shows it.

## Why attackers care
Configuration Manager is a code-execution service by design. Misconfiguration
Manager's TAKEOVER and ELEVATE techniques are all routes to *site control*,
and site control is SYSTEM on every client, domain controllers included. An
SCCM administrator account is rarely protected like a Domain Admin, so it is
a cheaper target.

## Before you change anything
- In the Configuration Manager console, check which collections hold the computer
  and which administrative users have rights on them (Administration >
  Security > Administrative Users, and each user's security scopes and
  collections).
- Decide which way to go: SCCM is either part of Tier Zero, or it must not
  manage Tier Zero.
- Note the current collection memberships and role assignments.

## Fix
### Option A: Take Tier Zero out of SCCM (recommended)
- Remove the client from the Tier Zero computers (`ccmsetup.exe /uninstall`), and
  exclude them from discovery and boundary groups so SCCM doesn't push it again.
- Or manage them from a separate site, or a hierarchy, administered only by
  Tier Zero admins.

### Option B: Make SCCM Tier Zero
Treat the site server, SMS Providers, the site database server, every Full
Administrator and every administrator of a collection that holds Tier Zero
computers as Tier Zero. Limit the roles of everyone else to collections without
Tier Zero computers, add those servers under Additional Tier Zero in Settings,
and fix what PW-003 and PW-004 report about them.

### Hardening either way
Require Extended Protection on the site database, SMB signing on site
systems, PKI or Enhanced HTTP instead of a network access account, no client
push account with admin rights on Tier Zero, and multi-admin approval for
scripts.

### PowerShell (ConfigurationManager module)
```powershell
# Administrative users, their roles and collections
Get-CMAdministrativeUser | Select-Object LogonName, RoleNames, CollectionNames

# Collections a device is in
Get-CMDevice -Name "<Computer>" | Get-CMResultantCollection | Select-Object Name, CollectionID

# Remove a collection from an administrative user's scope
Remove-CMCollectionFromAdministrativeUser -AdministrativeUserName "<Domain>\<User>" -CollectionName "<Collection>"
```

## Verify
Collect again with ConfigManBearPig **and its coverage file**, then analyze
the new collection. The finding is fixed when the computer is
no longer a client, or only Tier Zero accounts and groups administer it. Without a
coverage file it stays open as "can't tell".

## Rollback
Reinstall the client (`ccmsetup.exe` with your usual properties) or restore
the administrative user's collections and roles from your notes.
