# PW-021: AD CS ESC13: issuance policy linked to a group

**Category:** Attack path
**Typical owner:** PKI / AD CS administrators (AD team for the linked group)

## What this finding means
A certificate template carries an issuance policy, and that policy is linked to an AD group through the msDS-OIDToGroupLink attribute. When someone logs on with a certificate from this template, the domain controller adds the linked group's SID to their logon token, so they get that group's access without being a member. Accounts and groups outside Tier Zero can enroll in the template.

## Why attackers care
This is ESC13 (a later addition to SpecterOps' "Certified Pre-Owned" series). The feature, "authentication mechanism assurance", is meant for things like "smart card logons get extra access". If the linked group is privileged and the template is broadly enrollable, an attacker enrolls (tools such as Certipy support this) and logs on with the certificate to gain the group's rights. Group membership reviews never show it, because nobody is actually a member.

## Before you change anything
- List linked issuance policies and their groups with the PowerShell below. Note which templates use each policy (template Properties > **Extensions** tab > Issuance Policies).
- Confirm whether authentication mechanism assurance is in use on purpose, and which systems grant access to the linked group (file shares, applications, admin rights). Removing the link removes that access for certificate logons.
- The linked group is, by design, a universal group with no members; check that this is still true.

## Fix
### Option A: Restrict enrollment on the template (recommended when the link is intentional)
1. certtmpl.msc > template > Properties > **Security** tab.
2. Remove Enroll / Autoenroll from broad groups; grant it only to the accounts that should have the linked group's access.
3. Consider also requiring CA certificate manager approval (**Issuance Requirements** tab) for templates linked to privileged groups.

### Option B: Remove the group link (when it is not needed)
1. Open ADSI Edit, connect to the **Configuration** naming context.
2. Browse to CN=OID,CN=Public Key Services,CN=Services,CN=Configuration,<forest root DN>.
3. Open the issuance policy object (its displayName matches the policy shown on the template's Extensions tab), select **msDS-OIDToGroupLink** and clear it.

### Option C: Remove the policy from the template
certtmpl.msc > template > Properties > **Extensions** tab > Issuance Policies > Edit, remove the linked policy. Certificates already issued keep the policy until they expire or are revoked.

### Then: review certificates already issued
Certificates issued before the fix still carry the policy and still add the
group at logon. Revoke those held by accounts that shouldn't have the group's
access (certsrv.msc > **Issued Certificates**, filtered by the template).

### PowerShell / certutil
```powershell
# Find issuance policies that are linked to a group (requires the ActiveDirectory module)
$config = (Get-ADRootDSE).configurationNamingContext
Get-ADObject -SearchBase "CN=OID,CN=Public Key Services,CN=Services,$config" `
    -LDAPFilter "(msDS-OIDToGroupLink=*)" `
    -Properties displayName, msPKI-Cert-Template-OID, msDS-OIDToGroupLink |
    Select-Object displayName, msPKI-Cert-Template-OID, msDS-OIDToGroupLink

# Option B: remove the link from one policy object
Set-ADObject -Identity "<PolicyObjectDN>" -Clear msDS-OIDToGroupLink

# Option C, as a stopgap: stop the CA issuing the template
certutil -config "<CAHost>\<CAName>" -SetCATemplates -<Template>
```

## Verify
- The Get-ADObject query no longer returns the policy (Option B), or the template's Security tab shows only the intended enrollees (Option A).
- Revoke any certificates already issued from the template to unintended accounts (certsrv.msc > Issued Certificates > All Tasks > Revoke Certificate).
- Collect again (or use Retest on the finding) and confirm the finding ID is gone. ESC13 needs the template's certificatepolicy property, which SharpHound collects and some other collectors do not.

## Rollback
Re-set msDS-OIDToGroupLink to the group's distinguished name (`Set-ADObject -Identity "<PolicyObjectDN>" -Replace @{'msDS-OIDToGroupLink' = '<GroupDN>'}`), restore the template's Security entries or issuance policy, or re-publish the template with `-SetCATemplates +<Template>`.
