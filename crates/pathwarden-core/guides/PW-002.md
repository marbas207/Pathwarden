# PW-002: Account or group outside Tier Zero can DCSync

**Category:** Attack path
**Typical owner:** AD / identity team

## What this finding means
A user, computer or group outside Tier Zero holds both directory replication
rights on the domain object: "Replicating Directory Changes" and "Replicating
Directory Changes All" (directly or through group membership). Together they let
it ask a domain controller for the password hash of any account.

## Why attackers care
DCSync (OS Credential Dumping: DCSync, T1003.006) lets an attacker who controls
this account or group pull the krbtgt hash and every admin hash remotely, without touching
a domain controller's disk. With the krbtgt hash they can forge golden tickets and
keep domain access until krbtgt is rotated twice. Tools such as Mimikatz and
Impacket secretsdump do this in one command.

## Before you change anything
- Identify what the account or group is. Legitimate holders besides domain controllers
  are rare: Entra Connect (MSOL_ / AAD sync) accounts, some identity governance,
  backup or password-sync products.
- Check whether it replicates: on domain controllers, audit
  "Directory Service Access" and look for event 4662 with the replication GUIDs
  `1131f6aa-9c07-11d1-f79f-00c04fc2dcd2` and `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2`
  and the account as subject.
- If it is a sync account that must keep the rights, do not remove them: treat the
  account and its server as Tier Zero instead (Option B).

## Fix
### Option A: Remove the replication rights (recommended when not needed)
1. In **Active Directory Users and Computers**, enable **View > Advanced Features**.
2. Right-click the domain, **Properties > Security > Advanced**.
3. Find entries for the account (or the group that grants it) with
   "Replicating Directory Changes" / "Replicating Directory Changes All".
4. Select each and click **Remove**, then **OK**.
5. If the right comes through a group, remove the account from that group instead.
### Option B: Keep the rights, manage the account as Tier Zero
1. Add the account and the server it runs on under Additional Tier Zero in Settings.
2. Restrict logon to that server to Tier Zero admins, protect the account
   (long random password or gMSA where the product supports it), and monitor
   event 4662 for replication from any other source.
3. If the sync server has been retired, disable the account and remove the
   rights as in Option A.

By default only Domain Controllers, Enterprise Domain Controllers and
Administrators hold both rights on the domain object.

### PowerShell
```powershell
Import-Module ActiveDirectory
$domainDN = (Get-ADDomain).DistinguishedName
$acl = Get-Acl -Path "AD:\$domainDN"

# Replication extended rights
$getChanges    = [Guid]"1131f6aa-9c07-11d1-f79f-00c04fc2dcd2"
$getChangesAll = [Guid]"1131f6ad-9c07-11d1-f79f-00c04fc2dcd2"

# Show who holds them
$acl.Access | Where-Object { $_.ObjectType -in $getChanges, $getChangesAll } |
    Select-Object IdentityReference, ObjectType, IsInherited

# Save the current descriptor, then remove the account's entries
$acl.Sddl | Out-File ".\domain-acl-backup.txt"
$acl.Access | Where-Object {
    $_.ObjectType -in $getChanges, $getChangesAll -and $_.IdentityReference -like "*<Account>"
} | ForEach-Object { [void]$acl.RemoveAccessRule($_) }
Set-Acl -Path "AD:\$domainDN" -AclObject $acl
```

## Verify
Re-run the "Show who holds them" query; only domain controllers, Enterprise Domain
Controllers, Administrators and intended sync accounts should remain. Collect again (or use Retest on the finding) and confirm the finding ID is gone.

## Rollback
Restore the saved descriptor:
`$acl = Get-Acl "AD:\$domainDN"; $acl.SetSecurityDescriptorSddlForm((Get-Content .\domain-acl-backup.txt)); Set-Acl "AD:\$domainDN" $acl`
