# PW-018: AD CS ESC6: CA accepts requester-supplied SANs

**Category:** Attack path
**Typical owner:** PKI / AD CS administrators (AD team for domain controller settings)

## What this finding means
The CA has the EDITF_ATTRIBUTESUBJECTALTNAME2 policy flag enabled. With it, any request may name an arbitrary identity in a subject alternative name attribute, regardless of how the template is configured. Accounts and groups outside Tier Zero can enroll in an authentication template on this CA, so they can request logon certificates for other accounts. ESC6a covers templates without the security extension (Kerberos logon); ESC6b covers Schannel logon where domain controllers map certificates by UPN.

## Why attackers care
This is ESC6 from SpecterOps' "Certified Pre-Owned". The flag turns every authentication template on the CA into an ESC1-style template. Tools such as Certipy add a SAN attribute naming a Domain Admin to an ordinary request and log on with the result. Since the May 2022 certificate-binding updates, plain ESC6 against Kerberos needs a template without the SID security extension or weak mapping on DCs, which is the combination this finding reports.

## Before you change anything
- Confirm the flag is set: `certutil -config "<CAHost>\<CAName>" -getreg policy\EditFlags` and look for EDITF_ATTRIBUTESUBJECTALTNAME2.
- Find out why it was enabled. It is commonly turned on for web server or Exchange certificates with several DNS names, or by an old how-to. Those templates can instead use "Supply in the request" with manager approval, or build DNS names from AD.
- Restarting Certificate Services briefly interrupts issuance (seconds); schedule it.

## Fix
### Option A: Disable the flag on the CA (recommended)
1. On the CA (or remotely with -config), remove the flag with certutil as shown below.
2. Restart Certificate Services (certsrv.msc > right-click the CA > All Tasks > Stop Service, then Start Service, or Restart-Service certsvc).
3. Repeat for every CA listed in findings for this rule.

### Option B: Also close weak mapping on the domain controllers the finding names
1. ESC6b: on each domain controller, check `HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\Schannel\CertificateMappingMethods` and remove the UPN bit (0x4). The value 0x18 (S4U2Self mappings only) is Microsoft's recommended setting after the 2022 updates.
2. A DC with no value set and a build older than the May 2022 update (KB5014754) uses the old default 0x1F, which includes UPN mapping. The finding names such DCs and their build: install the current Windows updates. Only the updates close it on a DC older than May 2022: 0x18 maps through the KDC, which checks no mapping before that update.
3. ESC6a on a DC the finding names by its build: install the current Windows updates. Before the May 2022 update the KDC checks no certificate mapping, whatever StrongCertificateBindingEnforcement says.
4. Test client-certificate (TLS/LDAPS) logons first; applications relying on UPN mapping will fail.

### PowerShell / certutil
```powershell
# Check the current policy flags
certutil -config "<CAHost>\<CAName>" -getreg policy\EditFlags

# Remove the flag (the minus sign clears only this bit)
certutil -config "<CAHost>\<CAName>" -setreg policy\EditFlags -EDITF_ATTRIBUTESUBJECTALTNAME2

# Restart Certificate Services on the CA so the change takes effect
Restart-Service certsvc

# ESC6b only, on each domain controller: inspect the Schannel mapping methods
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\Schannel" -Name CertificateMappingMethods
```

## Verify
- `certutil -getreg policy\EditFlags` no longer lists EDITF_ATTRIBUTESUBJECTALTNAME2.
- A test request carrying a SAN attribute (for example certreq with `-attrib "SAN:upn=someone@domain"`) is issued without that SAN.
- Collect again (or use Retest on the finding) and confirm the finding ID is gone. The flag is read from the CA registry; make sure your collector reports it (SharpHound does), or run `scripts\Get-PathwardenTierZeroSettings.ps1` on the CA and add its file.

## Rollback
`certutil -config "<CAHost>\<CAName>" -setreg policy\EditFlags +EDITF_ATTRIBUTESUBJECTALTNAME2` followed by `Restart-Service certsvc`. For ESC6b, restore the previous CertificateMappingMethods value.
